# GemFlow 分支与 Worktree 维护

## 范围与授权

覆盖 GemFlow WebNext 和 GemFlow Services 两个本地仓库。先读各仓 `AGENTS.md`，遵守并发工作区、业务确认与发布边界。

| 本次意图 | 行为 |
| --- | --- |
| 列分支、检查合并、对比改动、查看大小 | 先只读盘点；未超过阈值只报告，超过时按已批准策略清理安全候选 |
| 创建 worktree 前、任务结束或合入 dev 后的空间维护 | 检查总量；超过下述阈值时执行已批准的安全清理策略 |
| 用户要求清理 worktree | 先检查；默认仍按阈值和安全门执行。用户明确要求“已合入 dev 的分支和 worktree 全部删除”时，按第 6 节执行全量清理（先备份后强制移除，活跃会话占用仍跳过） |
| 创建、编辑或解释本技能 | 只处理技能，不因此执行清理 |

项目已有用户授权：额外 worktree 总量超过 1 GiB 时，开始清理最久未使用的安全候选。用户明确要求“只看”“不要删”时，本轮始终只读；安全门不满足则不删除。技能是操作时的检查流程，不是定时任务或后台监控。全量清理（第 6 节）不是常备授权，每次都需要用户明确指示；脏目录强制移除永远以先备份为前提。

**清理授权只包含合格 worktree 的工作目录。** 保留本地分支、提交、主工作区与共享 Git 历史；提交、合并、推送、删分支、发布及服务器／数据库操作仍需另行明确授权。第 6 节的全量清理即由用户当次明确指示触发，授权范围只覆盖当次核实的目标集合。

## 1. 定位与盘点

参考 [只读命令与核对方法](references/inspection.md)。从当前项目的 Git 元数据定位主仓库；Services 默认是前端主仓库同级的 `GemFlow-Services`，不能硬编码用户名或旧 worktree 路径。路径不符合布局时询问或使用用户指定路径。

分别读取两仓：

- `refs/heads/` 中的本地分支、当前分支、HEAD 和关联 worktree。
- 每个分支相对**本地 `dev`**的祖先关系与独有提交数。
- `git worktree list --porcelain` 中所有注册目录，包括 detached、locked 和 prunable 状态。
- 每个分支和每个 worktree 的创建时间：分支取分支 reflog 首条，worktree 取目录 birth time 并与 `.git/worktrees/<名>` 管理目录 birth time 互证，命令见 [只读命令与核对方法](references/inspection.md)。
- 每个存在的目录的暂存、未暂存、未跟踪状态。

完成标准：两个仓库的分支和目录均有结果，每个分支和 worktree 的创建时间都有证据出处；仓库、路径或 `dev` 缺失时明确报告，不能把“检查失败”写成“已合并”。只读检查不需要 fetch，不把 `origin/dev` 当作本地 `dev`。

## 2. 区分“提交已合并”与“工作区已收齐”

`merge-base --is-ancestor <分支> dev` 成功，只证明**提交历史**被 dev 包含，不能证明未提交内容已保留。

对每个脏 worktree，把所有 Git 可见改动（含暂存、未暂存、删除、重命名和未跟踪文件）与本地 dev 比较：

| 类别 | 判定与处理 |
| --- | --- |
| 与 dev 相同 | 内容、文件类型、可执行位或符号链接目标均一致；记为已收录，但目录仍是脏的 |
| dev 已有后续版本 | 结合分支基线、双方 diff 和 dev 文件历史确认是旧副本；不能仅凭修改时间、行数或文件不同作结论 |
| 独有内容 | dev 没有该改动或文件；列出路径并保护，不自动合并、覆盖或丢弃 |
| 无法判断 | 按独有内容保护，说明待确认点 |

未跟踪文件也要查 dev：它可能已被别的提交收录。dev 没有的文件，可再与**主工作区中的未提交副本**比较；即使两份相同，也只能说“主目录有副本”，不能说“已提交”。

`node_modules` 等依赖链接单独统计，不当作业务源码差异。文档也要检查独有段落。只查看必要差异，不打印 `.env`、凭据、私钥或业务数据内容。

完成标准：每个脏目录都被逐项分类；报告分别回答“分支提交是否已合并”和“是否还有独有未提交内容”。

## 3. 空间口径与阈值

- 统计两仓**全部额外 worktree 的合计**，不含前后端主目录；当前使用中的额外 worktree 也计入总量，但受保护不能删。
- 使用 `du -sk` 对每个注册目录单独测量后相加；不使用 `-L` 跟随符号链接，不把链接目标的主目录依赖再次算入。
- 阈值固定为 **1 GiB = 1024 MiB = 1,048,576 KiB**。只有总量严格大于该值才触发阈值清理，等于或低于时不触发。
- 报告目录总量，并在需要解释时拆出实体 `node_modules`、构建产物和其余文件；子项不能重复加进总量。
- pnpm 硬链接、APFS 克隆等可能共享物理块。这里是可重复的 `du` 统计口径，不能承诺删除后一定释放同等物理空间。
- 不完整的盘点、测量错误、离线磁盘或失效路径意味着总量未知；不能拿部分合计触发删除。只报告缺口。

## 4. 超阈值时：先确定安全候选，再按最久未使用排序

“最远的”按**最久未使用**理解，不按与 dev 相差的提交数排序。

只有同时满足以下条件的目录，才可自动清理：

1. 是已核实的额外 worktree，不是任何主目录、当前会话工作目录或本次正在操作的目标目录。
2. 任务已结束且无其他开发者／Agent 正在使用；不承载 Vite 4176、API 3000、测试、终端任务等。无进程证据并不能单独证明无人使用；归属不明则跳过。
3. Git 未标记 locked；不处于 merge、rebase、cherry-pick 等未完成操作；detached 或 prunable 情况默认跳过并报告。
4. HEAD 已包含在对应本地 dev 中；分支没有需要保留的未合入提交。
5. 暂存、未暂存和未跟踪内容均干净。**脏目录即使与 dev 相同，也不自动 reset、clean、stash 或强制移除。** 先报告／备份，处置需单独确认。
6. 已枚举 Git 忽略的路径：仅确认可重建的依赖／缓存／构建产物可随目录删除；有 `.env`、私钥、本地数据库、上传文件、独有截图或其他未知文件时先保护并跳过。Git 显示 clean 不代表没有这些文件。

排序证据优先使用已有的任务结束／最后使用记录；缺失时可用 HEAD 最近 reflog 时间，最后退回 HEAD 提交时间，但必须标为**估计**。单纯读取或 `du` 不算使用，不更新使用时间；依赖安装后的目录 mtime 也不是可靠的最后使用时间。时间相同按规范化路径稳定排序。

完成标准：列出候选的路径、分支、占用、排序依据与安全门；受保护目录写明跳过原因。不能为了凑够空间绕过安全门。

## 5. 清理与留痕

- 清理前在前端 Git common dir 下用原子目录创建维护锁，记录本次所有者；已有锁时停止，不自行删除他人的锁。只读检查不加锁。
- 记录拟删目录的 HEAD、分支、大小和保护检查结果。备份必须放在所有待清理 worktree **之外**。
- 需要保护未提交内容时，分别保存暂存和未暂存的二进制 diff、未跟踪文件实际内容及校验清单；单份 diff 不能保存未跟踪文件。备份目录限制访问，不自动打包或输出未知敏感内容。**备份成功也不等于授权强制删除。**
- 每移除一个目录前，重新确认路径、HEAD、分支祖先关系、Git 状态、忽略文件与使用情况；有任何变化就跳过重新评估。
- 只通过对应主仓库运行 `git worktree remove -- <已核实目录>`，不带 `--force`。命令拒绝时停止处理该候选，不改用 `rm -rf`、`reset --hard` 或 `clean` 绕过。
- 每成功移除一个目录，立即重新统计双仓合计；降到 **≤ 1 GiB** 即停止，不继续删除其他旧目录。
- 没有安全候选时，即使仍超阈值也停止并报告阻塞项；不删分支、不清理共享依赖缓存、不执行全局 prune。
- 完成后核对分支引用和主工作区未提交内容均保留，释放自己持有的锁。清理中断或部分失败时如实记录已完成项，不声称全部成功。

## 6. 用户明确授权的全量清理

用户明确要求“已合入 dev 的分支和 worktree 全部删除”（含脏目录）时才进入本节；这是当次授权，不是常备策略，不改变第 4 节的自动阈值清理。目标集合：除 `dev`、`main` 外所有已合入本地 dev 的分支，及其全部 worktree。

1. **先备份，后删除**：每个脏 worktree 的未提交内容先备份到所有待删目录之外（命令见 [只读命令与核对方法](references/inspection.md)）——暂存与未暂存二进制 diff、未跟踪业务文件实际内容（排除 node_modules 等依赖）、与主工作区不同的忽略文件；与主工作区逐字节一致的副本可不备，但记录中写明。每个备份含分支、HEAD、条目数与校验清单。
2. **逐目录复查后移除**：分支仍合入 dev、无进程占用；干净目录普通 `worktree remove`，已备份的脏目录 `--force`。这是第 5 节“不带 --force”的唯一例外，前提是用户明确授权且备份已落盘；仍禁止 `rm -rf`、`reset --hard`、`clean` 绕过。
3. **活跃会话占用即跳过**：lsof 发现任何进程（含 shell 停在目录内的 cwd）先查明归属；其他 Agent／开发者正在使用的目录及其分支保留并报告，不阻塞其余目录。
4. **删分支只用 `git branch -d`**（未合入自动拒绝），保留 `dev` 与 `main`；记录每个已删分支名与 tip，便于 `git branch <名> <tip>` 恢复。
5. **移除因此变空的父目录**；目录内仍有非 Git 未知内容（如基线快照）时不删，单独报告待确认。
6. 全程加锁留痕；完成后按输出一节报告，附备份位置与恢复方法。

完成标准：任何 `--force` 之前备份已落盘且可独立恢复；活跃会话目录未被触碰；`dev`、`main`、主工作区及其未提交内容保留；删除与跳过逐项有记录。

## 输出

分支与 worktree 分表列出，每仓一组，均按创建时间排序：

- 分支表列：`创建时间 / 分支 / 建自 / 合入 dev / 落后 dev`。
- worktree 表列：`落成时间 / worktree / 分支 / 未提交条目数 / MiB`，主目录也列入。

表后给读表要点：分支先建而 worktree 后落成的时间差、成组批量创建、两层证据不一致之处；脏目录的未提交内容分类结论按第 2 节在正文给出。

结尾给出：额外 worktree 总量、是否超过阈值、本轮只读或已清理、跳过原因，以及未推送／未发布。区分“已合并”“可清理”“实际释放空间”，不把本次数字写成永久结论。全量清理轮次另附：删除清单（分支记 tip）、备份位置与恢复方法、活跃会话跳过项。
