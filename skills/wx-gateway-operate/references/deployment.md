# 部署运维

发布、配置或克隆实例时读取。部署流程使用 bounded-deployment-operations；当前运行目标为 wx-gateway，莆阳未获明确恢复前禁止启动。生产变更授权不来自本文件。

## 发布事务

1. 确认本地精确提交、未提交工作、运行目标 project/host/port/目录以及实际 PM2 用户和 PM2_HOME。保留业务方无关工作，包从 Git 提交导出。
2. 备份当前配置、数据库和可恢复应用包。保留运行时数据路径。制品包含 lockfile 和 pnpm-workspace.yaml，不纳入真实 .env、测试 fixture 和构建缓存。
3. 检查数据库迁移历史与实际 SQL，只执行增量 migrate deploy；权限不足先解决执行身份，不能改用数据丢失选项。generate/build/迁移顺序按目标受控清单执行；SSO 中央协议先于依赖它的客户端。
4. 检查 package build 是否含删除 env、seed、自动迁移等副作用。需要 NEXT_PUBLIC 配置的二维码组件在构建阶段注入真实网关 base/app，不能只修改运行环境。
5. 只激活已获准目标；检查应用任务终态及 stderr，不以 Azure 外层 exit 0 判成功。回读精确版本、监听 PID/cwd、服务状态与公网行为，处理完本次阻塞即停止。

公有 deploy API 关闭或 SSH 不可用时，使用已授权云 guest-command：下载私有短期制品、核对 SHA-256、读取服务器保护配置、通过 loopback 调部署服务。不得开放公网管理端来绕路；签名制品 URL 不进入日志。

## 远程执行

凭据通过 vault 或实际运行配置在内存读取，禁止输出或拼入 shell argv。调用 API 的 JSON 用序列化构造，shell 动态值使用正确引用。Node 临时脚本放项目目录以便解析 @prisma/client，使用唯一文件名并 finally 清理。程序输出仅允许操作结果与安全元数据，不原样转发配置、stdout/stderr 中的秘密。

对已有 /api/exec 的调用，先核对其入口可用性和授权；API 不可用不能假报操作成功。已有脚本失效时先读实际脚本，不能从过时示例重新猜认证。不得使用编码或替换工具绕过审批拒绝。

## 新公众号实例

只有用户明确要求新公众号实例才克隆；同公众号增加业务应用应注册 App。先查现有监听端口，准备独立数据库、issuer/key、公众号凭据、管理员会话密钥和隐藏后台路径。密钥从保护机制生成并保存；不要复用另一实例的会话密钥。

完整环境字段以仓库配置消费点和现有部署清单为准，至少核对数据库、WX_APPID/WX_APP_SECRET/WX_TOKEN/WX_AES_KEY、PUBLIC_BASE_URL、PORT、管理员引导配置；启用 SSO 时核对 SSO_ISSUER/SSO_SESSION_KEY。不要借用已撤销业务项目作为数据库跳板。

先部署并验证入口、迁移与验签，再由用户或获授权操作更新微信平台唯一 callback。核对微信明文/密文模式与代码能力一致。管理员真实登录、普通用户权限边界、注册客户端及手机扫码分别验收。停止或删除实例属于另外的操作范围，不套用接入撤销步骤。
